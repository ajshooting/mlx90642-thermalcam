# Safariで背面カメラと熱画像を表示する

iPhoneのカメラAPIは信頼できるHTTPS接続が必要です。HTTPの警告をオフにしても、`http://192.168.4.1`からカメラを起動することはできません。[WebKitの説明](https://webkit.org/blog/7763/a-closer-look-into-webrtc/)

この構成は、XIAOでHTTPSとWSSを配信し、iPhone内で背面カメラの映像と熱画像を組み合わせます。インターネット・外部サーバ・専用アプリは不要です。初回だけ、自分のMacで作ったルート証明書をiPhoneに登録して信頼します。

## Macでの準備

リポジトリのルートで実行します。Pythonはuv、証明書の生成はOpenSSLを使います。追加のPythonパッケージやArduinoライブラリは不要です。このMacではOpenSSL 3.6.3を確認しています。

```sh
uv run --no-project tools/generate_tls.py
```

`.local/tls/`に証明書と秘密鍵、`firmware/wifi_camera/tls_credentials.h`に基板へ書き込むデータを生成します。画面に出た**Local CA SHA-256**を、iPhoneでの設定時に照合してください。再実行しても同じCAとサーバ証明書を使います。

生成後に[../firmware/wifi_camera/wifi_camera.ino](../firmware/wifi_camera/wifi_camera.ino)をArduino IDEで開いて書き込みます。ボードは`XIAO_ESP32C3`、`USB CDC On Boot`は`Enabled`です。生成済みヘッダがある場合はHTTPSモードになり、温度データもWSSで送ります。

## iPhoneで一度だけ行う設定

1. XIAOを給電し、Wi-Fiの**ThermalCam**に接続します。パスワードは**thermalcam**。
2. Safariで**`http://192.168.4.1/setup`**を開きます。HTTPS-onlyのエラーで開けない場合は、「設定 → アプリ → Safari」の「接続が安全ではないときに警告」を一時的にオフにします。
3. 設定ページのSHA-256が、Macの生成コマンドで表示された値と一致することを確認し、「この基板の証明書をダウンロード」を押します。
4. 「設定 → 一般 → VPNとデバイス管理」（または設定トップの「プロファイルがダウンロード済み」）から**ThermalCam Local CA**をインストールします。
5. **「設定 → 一般 → 情報 → 証明書信頼設定」**で、**ThermalCam Local CAを信頼**します。証明書のインストールだけではSSL/TLSの信頼設定は有効になりません。[Appleの手順](https://support.apple.com/ja-jp/102390)
6. ThermalCamへ接続したまま、Safariの新しいタブで**`https://192.168.4.1/`**を開きます。証明書警告が出る場合は、信頼設定と日付・時刻を確認します。警告を無視して先へ進むだけでは完了になりません。
7. **「背面カメラを使う」**を押し、Safariのカメラ許可を選びます。HTTPの警告設定は元に戻せます。以後はHTTPSのURLを開きます。

Safariのカメラ設定を以前拒否している場合は、このサイトのカメラ設定を「確認」または「許可」に変更してください。カメラは自動で起動せず、停止ボタン・ページを離れる操作・背景への移動で停止します。戻ったときは開始ボタンを押し直します。

## 表示の選択と調整

カメラ開始後の「合成方法」で切り替えます。カメラ映像の縦横比に表示領域を合わせ、映像全体を表示します。

| 合成方法 | 表示・調整 |
| --- | --- |
| PiP（小窓、初期設定） | カメラ全体の内側に独立した熱画像を表示します。四隅の選択、大きさ、左右・上下の位置、濃さを調整できます。小窓の位置は、カメラ内の測定位置を示しません。 |
| 重ね合わせ | カメラに半透明の熱画像を重ねます。熱画像の大きさ・位置・濃さを調整します。 |
| 輪郭合成 | 熱画像の領域に対応するカメラ映像から明暗の境界を抽出し、白い輪郭と暗い縁を足します。大きさ・位置・濃さに加え、輪郭の強さ・感度を調整できます。 |

大きさ・位置・濃さは表示方法ごとに覚えます。表示方法と調整値はこの端末のブラウザに保存され、再読み込み後も使えます。「この表示をリセット」で選択中の表示を初期値に戻します。保存するのは調整値だけで、画像・映像は保存しません。

重ね合わせ・輪郭合成では、センサをiPhoneの背面カメラと同じ向きに固定し、「熱画像の大きさ」「左右の位置」「上下の位置」で見たい対象に合わせます。小窓の熱画像をタップすると、元の32×24画素の温度を読み取れます。

輪郭抽出は[Sobelフィルタ](https://docs.opencv.org/4.x/d2/d2c/tutorial_sobel_derivatives.html)による通常の画像処理で、AIや追加ライブラリは使いません。端末内で160×120画素、最大8回/秒で処理します。物体の認識や自動位置合わせ、熱画像の解像度・温度精度の向上は行いません。温度データが途切れた場合は、古い熱画像へ現在の輪郭を足さないよう輪郭を止めます。

**重ね合わせは未校正です。** カメラとセンサの画角・位置が違うため、距離を変えるとずれます。画面上の一致だけで物体の温度を断定せず、元の熱画像と測定位置を確認してください。iPhoneのカメラ映像は端末内で表示し、XIAOや外部へ送信・保存する処理はありません。

## 証明書の保存と更新

CAの秘密鍵はMacに残し、XIAOにはサーバの秘密鍵だけを書き込みます。`.local/`と`tls_credentials.h`はGit管理から除外しています。秘密鍵を共有・コミットしないでください。ルート証明書の信頼はこのiPhone全体に影響するため、自分で生成したものを使い、不要になったら「VPNとデバイス管理」から削除できます。

サーバ証明書の有効期間は365日です。期限が近づいたら、次のコマンドでサーバ証明書を更新して書き込み直します。CAを維持するので、iPhoneへルート証明書を登録し直す必要はありません。

```sh
uv run --no-project tools/generate_tls.py --renew
```

`.local/tls/`を削除すると、次に生成するCAは別物になります。その場合はiPhone側も新しい証明書へ入れ替えます。`tls_credentials.h`を削除して書き込めば従来のHTTP版になります。別のMacでは証明書を各自生成してください。共通の秘密鍵はリポジトリへ含めていません。

## 確認範囲

OpenSSLでの証明書チェーン・IPアドレス・用途の検証、カメラ開始／キャンセル／停止、PiPの配置・輪郭抽出・設定復元のテスト、XIAO ESP32-C3向けのコンパイルを行っています。**実機のiPhoneでの証明書登録・背面カメラ表示・HTTPSでの連続配信は別途確認が必要です。**

検証コマンド:

```sh
node --test tests/*.test.mjs
uv run --no-project python -B tests/test_tls.py
uv run --no-project tools/embed_web_ui.py --check
```

[ESP-IDFのHTTPSサーバ](https://docs.espressif.com/projects/esp-idf/en/latest/esp32c3/api-reference/protocols/esp_https_server.html)を使っています。証明書はECDSA P-256／SHA-256、IPのSAN、serverAuth用途で作り、[Appleの証明書要件](https://support.apple.com/en-us/103769)に沿った構成です。

Macのローカル画面を確認する場合は、`uv run --no-project tools/preview_server.py`で起動します。`http://127.0.0.1:8765/__test/camera`は熱画像・カメラとも模擬データを使い、物理カメラの許可を要求せずPiP・重ね合わせ・輪郭合成を確認できます。
